Moving backward without running code backward

The snapshot model behind Algorithm Studio, and why every panel reads the same moment.

Danny Perojevic · October 13, 2026· Updated October 15, 2026

Why I did not try to undo Python

Algorithm Studio lets someone step backward through a run. Undoing each Python operation would mean defining an inverse for every mutation, including code a visitor edits. Instead, Python runs forward and records snapshots. Going backward means selecting an earlier snapshot.

One frame for every panel

The browser worker emits the source line, variables, and visual state. The app validates and stores each frame. The editor highlight, diagram, variable inspector, and explanation then read the same selected frame. If the timeline says frame seven, every panel needs to describe frame seven.

A swap makes this easy to see

In the Bubble Sort example, I can move to a swap and compare it with the preceding frame. The array shows the changed positions while the source highlight shows the relevant line. Moving backward does not execute a reverse swap. It reads the state saved before that operation.

The cost of keeping the history

Snapshots take memory, so the application bounds the number of frames and the execution time. That is the tradeoff behind the playback model. A new algorithm can reuse the timeline by emitting the same frame contract, instead of needing its own system for stepping backward.
